# Move 4: a container is throwaway

## What it is

Everything a container writes to its own filesystem dies with it. `docker rm` removes the container and its writable layer. `docker run` from the same image gives a fresh container that remembers nothing. Only two things carry over: the image, and whatever you mounted from outside with `-v`.

This is why Kubernetes can kill and replace pods freely, and why state lives in volumes.

## Try

Part A, with a volume:

```
cat data/visits.txt
docker rm -f move3
docker run -d --name move3 -p 8010:8000 -e GREETING=moves -v "$(pwd)/data:/data" k8s-game/training
curl http://localhost:8010                          # the count continues
```

Part B, without a volume:

```
docker run -d --name move4 k8s-game/training
docker exec move4 wget -qO- http://127.0.0.1:8000
docker exec move4 wget -qO- http://127.0.0.1:8000
docker rm -f move4
docker run -d --name move4 k8s-game/training
docker exec move4 wget -qO- http://127.0.0.1:8000   # the count starts again
```

Notice part B: no `-p`, yet wget works from inside. Inside the container, localhost means the container itself. Keep that in mind for the boss.

## Task

`answers/4.txt`, two lines. Line 1: the visit count after the move3 restart in part A. Line 2: the visit count after the move4 restart in part B. Leave `move4` running without any volume.
