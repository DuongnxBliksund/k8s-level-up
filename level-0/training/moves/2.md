# Move 2: read the state

## What it is

Three ways to look at a running container without stopping it.

- `docker logs <container>`: what the main process wrote to stdout and stderr. First stop for "why did it crash".
- `docker inspect <container>`: everything Docker knows about it, as JSON. Network, mounts, env, state. Add `-f` with a template to pick one field.
- `docker exec <container> <command>`: run a command inside. What you see in there is what the app sees.

## Try

```
docker logs move1-a
docker inspect move1-a | less              # q to quit
docker inspect -f '{{.State.Status}}' move1-a
docker exec move1-a hostname
docker exec move1-a env
docker exec move1-a cat /etc/hosts
docker exec -it move1-a sh                 # exit to leave
```

## Task

Find the IP address of `move1-a`. There is a route from outside (inspect) and a route from inside (exec). Try both and see that they agree. Write the address on the first line of `answers/2.txt`.
