# Move 1: image versus container

## What it is

An image is a read-only template: a stack of filesystem layers plus metadata (the command to start, environment variables, the port the app uses). A container is one running instance of an image, with its own thin writable layer on top. One image can run as many containers as you like, each with its own process, its own filesystem changes and its own IP address.

Build makes images. Run makes containers.

## Try

```
cat app/Dockerfile
docker build -t k8s-game/training app
docker images k8s-game/training
docker run -d --name move1-a k8s-game/training
docker run -d --name move1-b k8s-game/training
docker ps
```

Look at the IMAGE and NAMES columns: one image, two containers.

## Task

Have the image `k8s-game/training` built and both containers `move1-a` and `move1-b` running from it.
